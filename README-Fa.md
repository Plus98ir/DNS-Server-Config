## 📌 معرفی
این اسکریپت یک نصاب و راه‌انداز خودکار (All-in-One) برای ایجاد یک سرور مسیریابی امن و پرسرعت است. این ابزار به‌طور خودکار ابزارهای ضروری برای مسیریابی ترافیک، مدیریت DNS، نظارت بر پهنای باند و کنترل دسترسی کاربران را نصب و پیکربندی می‌کند. این اسکریپت طوری طراحی شده است که عمومی بوده و روی هر سروری قابل پیاده‌سازی باشد.

### 🚀 ویژگی‌ها و عملکردهای اسکریپت


> ⚠️ **توجه مهم:** هنگام وارد کردن رمز عبور نهایت دقت را داشته باشید. در صورت دو مرتبه ورود ناموفق، سیستم به‌طور خودکار IP دستگاه شما (کامپیوتر یا گوشی که با آن متصل می‌شوید) را مسدود می‌کند؛ بنابراین منظور IP سرور نیست و در صورت بروز این مشکل، برای اتصال مجدد ناچار خواهید بود IP دستگاه خود (مودم یا اینترنت سیستم خود) را تغییر دهید.


هنگام اجرای این اسکریپت، وظایف زیر به‌طور خودکار انجام می‌شوند:



۱. **آپدیت سیستم و پیش‌نیازها:** سیستم‌عامل را به‌روزرسانی کرده و پکیج‌های مورد نیاز (`curl`, `wget`, `iptables`, `vnstat`, `ipset`, `iftop`, `nethogs`, `jq` و غیره) را نصب می‌کند.



۲. **بهینه‌سازی شبکه (BBR):** الگوریتم TCP BBR و `fq_qdisc` را برای کنترل بهینه ترافیک شبکه و افزایش سرعت، فعال و پیکربندی می‌کند.



۳. **نصب X-UI (ثنایی):** در صورتی که پنل 3X-UI از قبل نصب نباشد، به‌طور خودکار آن را برای مدیریت پروکسی‌ها نصب می‌کند.



۴. **پیکربندی AdGuard Home:** (توضیحات این بخش را اینجا ادامه دهید...)



نصب **AdGuard Home** با یک کانفیگ عمومی سفارشی‌سازی شده (Bind IP: 0.0.0.0).

بهینه‌سازی حجم کش، غیرفعال‌سازی لاگ‌های غیرضروری و ایمن‌سازی DNS در برابر سوءاستفاده‌های عمومی.

۵. کنترل دسترسی پویا (IPSet و IPTables):

اسکریپت restore_rules.sh: بازسازی قوانین NAT و Mangle در زمان ریبوت سیستم تا ترافیک مجاز مستقیماً به پورت‌های X-UI محلی هدایت شود.

**اسکریپت** adguard-monitor.sh: اسکن لاگ‌های AdGuard Home برای یافتن آی‌پی کلاینت‌های جدید و افزودن پویای آن‌ها به IPSet با نام allowed_users با محدودیت زمانی ۱ ساعته.

۶. **آپدیت خودکار قوانین از گیت‌هاب**:

دریافت خودکار لیست دامنه‌های تمیز شما از گیت‌هاب، نادیده گرفتن کامنت‌های # و اضافه کردن $dnsrewrite=[YOUR_SERVER_IP] به انتهای آن‌ها.

تنظیم یک کرون‌جاب (cronjob) برای به‌روزرسانی خودکار این لیست هر ۱۲ ساعت یک‌بار.

۷. مدیریت حجم ترافیک و ابزارهای خط فرمان (CLI):

اسکریپت traffic.sh (دستور hajm): محاسبه دقیق مصرف پهنای باند، سهمیه باقی‌مانده و انجام ریست‌های ماهانه.

اسکریپت display.sh: نمایش یک بنر متنی (ASCII) زیبا از ترافیک باقی‌مانده به‌صورت خودکار هنگام ورود به SSH.

اسکریپت panel.sh (دستور menu): یک منوی تعاملی در خط فرمان برای مشاهده کاربران فعال، نظارت بر پهنای باند، مدیریت بلک‌لیست‌ها و راه‌اندازی مجدد سرویس‌ها.

**توجه:** پیش از اقدام به نصب، اطمینان حاصل کنید که پورت ۵۳ سرور توسط سرویس دیگری اشغال نشده باشد.

فایل تنظیمات مربوطه را باز کرده، عبارت DNSStubListener=yes را از حالت کامنت خارج کنید و آن را به مقدار DNSStubListener=no تغییر دهید. 

```txt
nano /etc/systemd/resolved.conf
```


سپس systemd-resolved.service را ریستارت کنید و اقدام به نصب نمایید.


```txt
systemctl restart systemd-resolved.service
```

⚙️ اقدامات مهم پس از نصب (تنظیمات X-UI)
تنها کاری که پس از نصب باید انجام دهید، تنظیم پنل X-UI ثنایی به شرح زیر است:

دو ورودی (Inbound) جدید از نوع Tunnel بسازید.

آدرس لیسنینگ (Listen IP) را برای هر دو روی 127.0.0.1 تنظیم کنید. اولی را روی پورت 443 و دومی را روی پورت 80 پیکربندی کنید.

در هر دو Inbound، مطمئن شوید که گزینه Sniffing فعال است و حتماً تیک گزینه‌های quic، http و tls را بزنید.

در نهایت، به بخش Routing Rules در پنل ثنایی بروید. این دو ورودی را به یک خروجی (Outbound) هدایت کنید (ترجیحاً تحت شرایط فعلی شبکه، به یک کانفیگ REALITY که به سرور خارج شما متصل است، یا هر خروجی دیگری که تحریم‌ها را دور می‌زند).

🔒 نحوه احراز هویت کاربران (تنظیمات Wildcard و کلاینت‌ها)
برای جلوگیری از استفاده شدن سرور شما به عنوان یک Open Resolver و دادن دسترسی خصوصی به هر کاربر، باید Client IDها را با استفاده از یک دامنه وایلدکارد (Wildcard) پیکربندی کنید:

تهیه دامنه Wildcard:
در پنل مدیریت DNS دامنه خود (مثلاً Cloudflare)، یک رکورد A با نام * (Wildcard) بسازید که به آی‌پی سرور شما اشاره کند. مطمئن شوید که یک گواهینامه SSL وایلدکارد (مانند *.yourdomain.com) دارید.
می‌توانید از Certbot استفاده کنید. ابتدا باید certbot را نصب کنید:
```txt
apt install certbot
```
سپس دستور دریافت گواهینامه را اجرا کنید:
```txt
certbot certonly \
--manual \
--preferred-challenges dns \
-d "*.yourdomain.com" \
-d "yourdomain.com"
```

شما باید 2 رکورد متنی (TXT) در کلودفلر خود اضافه کنید؛ مرحله به مرحله طبق راهنمای Certbot پیش بروید.
سپس مسیر گواهینامه‌های خود را به این شکل دریافت خواهید کرد:
```txt
/etc/letsencrypt/live/yourdomain.com/fullchain.pem
```
```txt
/etc/letsencrypt/live/yourdomain.com/privkey.pem
```
سپس مانند تصویر به بخش Settings > Encryption بروید:

(خط قرمز در این تصویر صرفاً یک مثال برای شماست؛ اگر آدرس معتبری بدهید، یک خط سبز رنگ خواهید دید.)

اگر سرویس دیگری روی پورت 443 دارید، مراقب باشید و از پورت 443 برای DoH استفاده نکنید.
از یک پورت دیگر استفاده کنید. پورت 443 امن است، اما اگر از پورت دیگری استفاده کنید، آدرس DoH شما به این شکل خواهد شد:

(https://yourdomain.com:8443/dns-query/yourclientname)

افزودن کلاینت‌ها در AdGuard Home:

وارد پنل وب AdGuard Home شوید.

به مسیر Settings > Client Settings بروید و روی Add Client کلیک کنید.

یک نام برای کاربر وارد کنید (مثلاً Sadeq-Pc).

در فیلد Identifiers، یک Client ID منحصربه‌فرد تایپ کنید (مثلاً sadeqpc1).

کلاینت را ذخیره کنید.

نحوه اتصال کاربر:
کاربر اکنون می‌تواند با استفاده از DoT یا DoH به صورت کاملاً امن متصل شود. AdGuard آن‌ها را از طریق شناسه (identifier) تشخیص خواهد داد:

DoT: (tls://yourclientname.yourdomain.com)

DoH: (https://yourdomain.com/dns-query/yourclientname)

توصیه می‌شود برای هر کلاینت از یک شناسه خاص (مانند 67ca2c09) استفاده کنید
اکنون کلاینت شما باید به این شکل استفاده کند:

DoT: (tls://67ca2c09.yourdomain.com)

DoH: (https://yourdomain.com/dns-query/yourclientname)

استفاده از شناسه کاربر (User ID) بسیار مهم است، اما از طریق نام کاربر می‌توانید در مدیریت لاگ AdGuard Home متوجه شوید چه کسی به سرور شما متصل شده است.
