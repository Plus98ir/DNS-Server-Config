## 🇮🇷 راهنمای فارسی

### 📌 معرفی

**توجه مهم:** هنگام وارد کردن رمز عبور نهایت دقت را داشته باشید. در صورت دو مرتبه ورود ناموفق، سیستم به‌طور خودکار آی‌پی دستگاه شما (رایانه یا تلفن‌همراهی که استفاده می‌کنید) را مسدود خواهد کرد.

این اسکریپت یک نصاب و راه‌انداز خودکار (All-in-One) برای ایجاد یک سرور مسیریابی امن و پرسرعت است. این ابزار به‌طور خودکار ابزارهای ضروری برای مسیریابی ترافیک، مدیریت DNS و کنترل دسترسی را نصب و پیکربندی می‌کند.

### 🚀 ویژگی‌ها و عملکردهای اسکریپت

هنگام اجرای این اسکریپت، وظایف زیر به‌طور خودکار انجام می‌شوند:

۱. **آپدیت سیستم و پیش‌نیازها:** سیستم‌عامل را به‌روزرسانی کرده و پکیج‌های مورد نیاز (`curl`, `wget`, `iptables`, `vnstat`, `ipset`, `iftop`, `nethogs`, `jq` و غیره) را نصب می‌کند.

۲. **بهینه‌سازی شبکه (BBR):** الگوریتم TCP BBR و `fq_qdisc` را برای کنترل بهینه ترافیک شبکه و افزایش سرعت، فعال و پیکربندی می‌کند.

۳. **نصب X-UI (ثنایی):** در صورتی که پنل 3X-UI از قبل نصب نباشد، به‌طور خودکار آن را برای مدیریت پروکسی‌ها نصب می‌کند.

۴. **پیکربندی AdGuard Home:**
   * نصب **AdGuard Home** با یک کانفیگ عمومی سفارشی‌سازی‌شده (Bind IP: `0.0.0.0`).
   * بهینه‌سازی حجم کش، غیرفعال‌سازی لاگ‌های غیرضروری و ایمن‌سازی DNS در برابر سوءاستفاده‌های عمومی.

۵. **کنترل دسترسی پویا (IPSet و IPTables):**
   * **اسکریپت `restore_rules.sh`:** بازسازی قوانین NAT و Mangle در زمان ریبوت سیستم تا ترافیک مجاز مستقیماً به پورت‌های X-UI محلی هدایت شود.
   * **اسکریپت `adguard-monitor.sh`:** اسکن لاگ‌های AdGuard Home برای یافتن آی‌پی کلاینت‌های جدید و افزودن پویای آن‌ها به IPSet با timeout ۱ ساعت.

۶. **آپدیت خودکار قوانین از گیت‌هاب:**
   * دریافت خودکار لیست دامنه‌های تمیز شما از گیت‌هاب، نادیده گرفتن کامنت‌های `#` و اضافه کردن `$dnsrewrite=[YOUR_SERVER_IP]` به آن‌ها.
   * تنظیم یک کرون‌جاب (cronjob) برای به‌روزرسانی خودکار این لیست هر ۱۲ ساعت یک‌بار.

۷. **مدیریت حجم ترافیک و ابزارهای خط فرمان (CLI):**
   
   * **اسکریپت `traffic.sh` (دستور `hajm`):** محاسبه دقیق مصرف پهنای باند، سهمیه باقی‌مانده و انجام ریست‌های ماهانه.

**توجه:** پیش از اقدام به نصب، اطمینان حاصل کنید که پورت ۵۳ سرور توسط سرویس دیگری اشغال نشده باشد.

فایل تنظیمات مربوطه را باز کرده، عبارت `DNSStubListener=yes` را از حالت کامنت خارج کنید و آن را به مقدار `DNSStubListener=no` تغییر دهید:

```bash
nano /etc/systemd/resolved.conf
```

سپس `systemd-resolved.service` را ریستارت کنید و اقدام به نصب نمایید:

```bash
systemctl restart systemd-resolved.service
```

### 🛠 آموزش نصب و استفاده

می‌توانید اسکریپت نصب را با استفاده از `curl` اجرا کنید:

```bash
bash <(curl -fsSL https://github.com/Plus98ir/DNS-Server-Config/releases/latest/download/install.sh)
```

در طول فرآیند نصب، از شما خواسته می‌شود تا اطلاعات زیر را برای AdGuard Home وارد کنید:

**آدرس لینک (URL) (برای رول‌ها)**

```txt
https://raw.githubusercontent.com/Plus98ir/AdGuard_Rules/refs/heads/main/unsanction-rules.txt
```

**پورت (Port)**

**نام کاربری (Username) و رمز عبور (Password)**

**نکته:** پیشنهاد می‌کنم برای رول‌ها از لینک اختصاصی من استفاده کنید. این یک لیست کامل برای دور زدن تحریم‌ها است که به‌طور مستمر به‌روزرسانی می‌شود.

پس از اتمام نصب، آدرس AdGuard شما به این شکل است:

```
http://your-ip:port
```

**نکته:** از آنجایی که این یک کانفیگ شخصی‌سازی‌شده است، تغییرات و تنظیمات بیشتر را می‌توانید مستقیماً در فایل `/opt/AdGuardHome/AdGuardHome.yaml` انجام دهید.

### 📜 قوانین مسیریابی پیش‌فرض

در طول مراحل نصب، اسکریپت از شما یک لینک گیت‌هاب درخواست می‌کند. اگر هنوز قوانین اختصاصی خود را ندارید، می‌توانید از لیست بهینه شده‌ی من استفاده کنید.

اما اگر قوانین مسیریابی شخصی دارید، بعد از وارد کردن لینک قوانین حتماً در ترمینال دستور زیر را وارد کنید:

```bash
/root/update-adguard.sh
```

در قسمت **Filters** و بخش **DNS blocklist** گزینه آبی رنگ **Check for updates** را بزنید.

### ⚙️ اقدامات مهم پس از نصب (تنظیمات X-UI)

تنها کاری که پس از نصب باید انجام دهید، تنظیم پنل X-UI سنایی به شرح زیر است:

1. دو ورودی (Inbound) جدید از نوع **Tunnel** بسازید.
2. آدرس لیسنینگ (Listen IP) را برای هر دو روی `127.0.0.1` تنظیم کنید. اولی را روی پورت 443 و دومی را روی پورت 80 پیکربندی کنید.
3. در هر دو Inbound، مطمئن شوید که گزینه Sniffing فعال است و حتماً تیک گزینه‌های quic، http و tls را بزنید.
4. در نهایت، به بخش Routing Rules در پنل ثنایی بروید. این دو ورودی را به یک خروجی (Outbound) هدایت کنید (ترجیحاً تحت شرایط فعلی شبکه، یک کانفیگ REALITY متصل به سرور خارجی).

### 🔒 نحوه احراز هویت کاربران (تنظیمات Wildcard و کلاینت‌ها)

برای جلوگیری از استفاده شدن سرور شما به عنوان یک Open Resolver و دادن دسترسی خصوصی به هر کاربر، باید Client ID‌ها را با استفاده از دامنه Wildcard پیکربندی کنید.

#### تهیه دامنه Wildcard

در پنل مدیریت DNS دامنه خود (مثلاً Cloudflare)، یک رکورد A با نام `*` (Wildcard) بسازید که به آی‌پی سرور شما اشاره کند. مطمئن شوید که دارای یک گواهینامه SSL Wildcard هستید (مثلاً `*.yourdomain.com`).

می‌توانید از Certbot استفاده کنید. ابتدا باید `certbot` را نصب کنید:

```bash
apt install certbot
```

سپس دستور دریافت گواهینامه را اجرا کنید:

```bash
certbot certonly \
--manual \
--preferred-challenges dns \
-d "*.yourdomain.com" \
-d "yourdomain.com"
```

شما باید 2 رکورد متنی (TXT) در کلودفلر خود اضافه کنید؛ مرحله به مرحله طبق راهنمای Certbot پیش بروید.

سپس مسیر گواهینامه‌های خود را به این شکل دریافت خواهید کرد:

```
/etc/letsencrypt/live/yourdomain.com/fullchain.pem
```

```
/etc/letsencrypt/live/yourdomain.com/privkey.pem
```

سپس مانند تصویر به بخش **Settings > Encryption** بروید.


<img width="1085" height="1321" alt="image" src="https://github.com/user-attachments/assets/6abdb7b6-a8f7-467c-8806-04ac50f5a890" />


**نکته:** اگر سرویس دیگری روی پورت 443 دارید، مراقب باشید و از پورت 443 برای DoH استفاده نکنید. از یک پورت دیگر استفاده کنید. اگر از پورت دیگری استفاده کنید، آدرس DoH شما به این شکل خواهد بود:

```
https://yourdomain.com:8443/dns-query/yourclientname
```

#### افزودن کلاینت‌ها در AdGuard Home

1. وارد پنل وب AdGuard Home شوید.
2. به مسیر **Settings > Client Settings** بروید و روی **Add Client** کلیک کنید.
3. یک نام برای کاربر وارد کنید (مثلاً Sadeq-Pc).
4. در فیلد Identifiers، یک Client ID منحصربه‌فرد تایپ کنید (مثلاً sadeqpc1).
5. کلاینت را ذخیره کنید.

#### نحوه اتصال کاربر

کاربر اکنون می‌تواند با استفاده از DoT یا DoH به صورت کاملاً امن متصل شود. AdGuard آن‌ها را از طریق شناسه (identifier) تشخیص خواهد داد:

**DoT:** `tls://yourclientname.yourdomain.com`

**DoH:** `https://yourdomain.com/dns-query/yourclientname`

**توصیه می‌شود برای هر کلاینت از یک شناسه خاص (مانند `67ca2c09`) استفاده کنید**

اکنون کلاینت شما باید به این شکل استفاده کند:

**DoT:** `tls://67ca2c09.yourdomain.com`

**DoH:** `https://yourdomain.com/dns-query/yourclientname`

استفاده از شناسه کاربر (User ID) بسیار مهم است، اما از طریق نام کاربری می‌توانید در مدیریت لاگ AdGuard Home متوجه شوید که چه کسی به سرور شما متصل شده است.
